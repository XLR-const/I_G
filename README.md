# I_G — 2.5D Shooter на Pygame

**I_G** — это шутер от первого лица в стиле Wolfenstein 3D, разработанный на Python с использованием Pygame. Игрок исследует лабиринты, сражается с врагами, собирает оружие и проходит уровни.

## Описание проекта

**Жанр:** 2.5D шутер от первого лица в стиле Wolfenstein 3D с элементами хоррора

**Игрок:** Солдат элитного отряда, пробивающийся через уровни, заполненные врагами. Управляет движением (WASD), прицеливанием (мышь), сменой оружия (клавиши 1-4 или колесо мыши).

**Цель:** Пройти 3 уровня, уничтожая всех врагов на каждом уровне и находя выход. Прогресс сохраняется между уровнями в файл.

**Описание:** Игра представляет собой шутер с псевдо-3D графикой, использующий рейкастинг для рендеринга стен. Игрок исследует лабиринты, сражается с 7 типами противников (от рядовых солдат до босса), использует 4 вида оружия. Уровни загружаются из JSON-файлов, прогресс автоматически сохраняется после прохождения каждого уровня. Перед каждой миссией показывается брифинг с картинкой и описанием задачи.

## Игровые механики

| Действие | Правило | Результат |
|----------|---------|-----------|
| Передвижение | WASD + мышь для поворота | Игрок перемещается по карте, не проходя сквозь стены и двери |
| Стрельба | ЛКМ / Пробел; учёт дистанции и угла | Враг получает урон; создаются частицы эффекта выстрела |
| Смена оружия | Клавиши 1-4 или колесо мыши | Меняется урон, скорострельность, анимация и звук выстрела |
| Поведение врагов | Конечный автомат (FSM) | Враги патрулируют, преследуют игрока, атакуют при виде |
| LOS (Line of Sight) | DDA луч от врага к игроку | Враг атакует/преследует только если видит игрока |
| Поиск пути | A* на сетке карты | Враги обходят стены, преследуя игрока |
| Двери | Автоматическое открытие при приближении | Создают проходы между комнатами, закрываются через задержку |
| Интерфейс | Сетка 16×9, компас, иконки HP | Игрок видит здоровье, текущее оружие, количество патронов, направление к выходу |
| Сохранения | JSON-файл после каждого уровня | Прогресс (номер уровня, количество убийств, время прохождения) сохраняется |
| Консоль разработчика | Открывается клавишей тильда (~) | Позволяет изменять уровень, HP, патроны во время игры для отладки |

## Требования

### Функциональные требования

1. Игрок может пройти минимум 3 полных уровня от старта до выхода
2. Игрок может выбирать оружие из 4 типов (пистолет, дробовик, автомат, плазмаган)
3. Противники (7 типов) корректно реагируют на игрока через конечный автомат
4. Прогресс сохраняется в файл и загружается при старте игры
5. Меню позволяет начать новую игру, загрузить сохранение, изменить настройки, выйти из игры

### Технические требования

| Требование | Значение |
|------------|----------|
| Частота кадров (FPS) | ≥ 30 при 10+ активных NPC |
| A* поиск пути | На карте 32×18 за < 50 мс |
| Загрузка уровня из JSON | < 2 секунд |
| Рейкастинг | 960 лучей на кадр при 60 FPS |
| LOS проверка | < 0.5 мс на NPC (с кэшированием) |

### Критерии готовности

- Главное меню с пунктами (Новая игра, Загрузить, Настройки, Выход)
- Меню паузы (Продолжить, Рестарт, Главное меню, Выход)
- Экран смерти с кнопками Restart / Main Menu
- Брифинг перед каждым уровнем
- Экран завершения уровня со статистикой убийств и времени
- Консоль разработчика для отладки
- Сохранение и загрузка прогресса

### Осознанные ограничения (что не реализовано)

- Нет мультиплеера
- Нет системы диалогов и NPC-союзников
- Нет редактора уровней в игре
- Нет процедурной генерации уровней
- Нет поддержки геймпада
- Нет физики объектов (только базовая коллизия)

## Архитектура

### Используемая архитектура: компонентно-ориентированная с разделением на системы

**Почему выбрана эта архитектура:**

1. **Разделение ответственности** — каждый класс отвечает за одну задачу (рендер, физику, искусственный интеллект)
2. **Тестируемость** — классы PathFinder и NPC можно тестировать изолированно от остальной игры
3. **Расширяемость** — новые типы оружия и NPC добавляются через наследование без изменения существующего кода
4. **Гибкость загрузки** — уровни в JSON позволяют менять контент без перекомпиляции

### Основные компоненты

| Компонент | Ответственность |
|-----------|------------------|
| **Game** | Главный игровой цикл, управление состояниями, загрузка уровней |
| **Player** | Позиция, здоровье, движение, обработка коллизий, регенерация HP |
| **Map** | Загрузка карты, проверка стен, хранение дверей и позиций NPC |
| **NPC** | Искусственный интеллект, конечный автомат, движение, атака, получение урона |
| **RayCasting** | DDA рейкастинг, Z-буфер, текстуры стен |
| **Renderer** | Отрисовка фона, интерфейса (компас, HP, оружие), FPS счётчика |
| **Weapon** | Стрельба, перезарядка, анимация, частицы, звуки |
| **PathFinder** | A* поиск пути по карте |
| **UIManager** | Все меню, брифинги, экраны смерти и завершения уровня |
| **LevelManager** | Загрузка уровней из JSON-файлов |
| **SaveSystem** | Сохранение и загрузка прогресса |
| **Console** | Консоль разработчика для отладки |

## Алгоритмы

### 1. DDA Рейкастинг

**Зачем:** Создание иллюзии трёхмерного мира из 2D карты.

**Где:** `raycasting.py`, метод `ray_cast()`

**Вход:** позиция и угол игрока, карта стен, двери

**Выход:** Z-буфер расстояний, отрисованные стены с текстурами

**Сложность:** O(NUM_RAYS × пересечённые клетки) ≈ 10 000 операций/кадр

**Фрагмент кода:**
```python
while not wall_hit:
    if side_dist_x < side_dist_y:
        side_dist_x += delta_dist_x
        x_map += step_x
        side = 0  # Вертикальная стена
    else:
        side_dist_y += delta_dist_y
        y_map += step_y
        side = 1  # Горизонтальная стена
    
    if (x_map, y_map) in self.game.map.world_map:
        wall_hit = True
```
2. A* Поиск пути
Зачем: Враги преследуют игрока, обходя стены.

Где: pathfinding.py, метод a_star()

Вход: позиция NPC и игрока, карта проходимости, max_distance

Выход: список клеток пути или пустой список

Сложность: O(количество клеток в радиусе) ≈ 25-64 клетки

Оптимизации: ограничение дистанции, max_iterations = 1000, манхэттенская эвристика

3. Line of Sight (LOS)
Зачем: Определение, видит ли NPC игрока через стены.

Где: npc.py, метод has_line_of_sight()

Вход: позиция NPC и игрока в клетках, карта стен

Выход: True (видит) или False (не видит)

Сложность: O(длина линии в клетках) ≈ 30

Оптимизация: кэширование результата на 150 мс

4. Другие алгоритмы
Алгоритм	Назначение	Сложность
FSM	Управление поведением NPC	O(1)
Система частиц	Эффекты выстрелов, крови	O(количество частиц)
